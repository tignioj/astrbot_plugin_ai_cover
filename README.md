# AstrBot AI 翻唱插件

这个插件把聊天平台收到的音频发给 Windows 上的 RVC 服务，按以下顺序处理：

> 本仓库包含 AstrBot 前端插件，需要配合 [RVC AI Cover Service](https://github.com/tignioj/RVC-AI-Cover-Service) 使用。

1. 对上传文件计算 SHA-256；若缓存命中，直接复用干人声和伴奏；
2. PyMSS `去伴奏`：得到人声和伴奏；
3. PyMSS `去混响`：得到干净人声，并将干人声和伴奏写入缓存；
4. RVC：使用 `assets/weights` 中指定的模型和 `logs` 中匹配的索引；
5. FFmpeg：按需对伴奏做保时长变调，混合翻唱人声，并以保持音高的方式变速后输出 320 kbps MP3。

## 启动 RVC 服务

在 Windows 项目根目录运行：

```bat
start-ai-cover-service.bat
```

默认监听 `0.0.0.0:18888`，限制上传 200 MiB、音频 15 分钟。可通过以下环境变量覆盖：

- `AI_COVER_HOST`
- `AI_COVER_PORT`
- `AI_COVER_API_TOKEN`
- `AI_COVER_MAX_UPLOAD_MB`
- `AI_COVER_MAX_AUDIO_SECONDS`
- `AI_COVER_CACHE_ROOT`（默认 `TEMP/ai_cover_cache`）

## 安装 AstrBot 插件

把本目录复制到 AstrBot 的：

```text
data/plugins/astrbot_plugin_ai_cover
```

重启 AstrBot 或在插件管理页重载。插件默认访问：

```text
http://127.0.0.1:18888
```

如果 AstrBot 运行在 Docker 中，或 RVC 服务位于另一台主机，请在插件配置中把 `service_url` 修改为 AstrBot 容器能够访问的地址。

## 指令

- `/翻唱模型`：列出模型与索引状态；
- `/翻唱`：使用插件配置中的默认模型（初始为“芙宁娜”）；
- `/翻唱 胡桃 0`：使用“胡桃”模型，人声不变调，BGM 变调和两个音量使用默认值；
- `/翻唱 胡桃 0 2`：人声不变调，BGM 升 2 个半音；
- `/翻唱 胡桃 0 2 1.2 0.8`：BGM 升 2 个半音，并使用 1.2 倍人声音量和 0.8 倍背景音乐音量；
- `/翻唱 胡桃 0 2 1.2 0.8 1.25`：在上述设置基础上以 1.25 倍速输出；
- `/翻唱下载 [模型] [人声变调] [BGM变调] [人声音量] [背景音乐音量] [变速]`：参数与 `/翻唱` 相同，但一定发送 MP3 文件；省略模型时也使用默认模型；
- `/翻唱状态`：检查 RVC 服务连接和任务状态。

完整格式为 `/翻唱 [模型] [人声变调] [BGM变调] [人声音量] [背景音乐音量] [变速]`。两种变调范围均为 -24～24 个半音；音量范围为 0～2，0 表示静音；变速范围为 0.5～2，默认 1，数值大于 1 会加快、小于 1 会减慢，并保持音高不变。BGM 变调会尽量保持伴奏原时长不变。

翻唱命令需附带音频，也可回复一条音频后发送。插件配置页可以修改默认模型、默认翻唱人声音量倍率和默认伴奏音量倍率；命令中的可选参数只覆盖当前任务。

“将结果作为语音消息发送”默认关闭：关闭时发送 MP3 文件；开启时，普通 `/翻唱` 会保留生成的 MP3 格式并交给消息适配器，不再经过 AstrBot 默认的 WAV 转换，以免 Base64 消息体积过大。`/翻唱下载` 始终发送 MP3 文件，不受此开关影响。返回的 MP3 附件名格式为 `AI翻唱-角色-源文件名.mp3`。消息平台仍可能再次转码或限制超长音频。

## 分离缓存

缓存键是上传文件原始字节的 SHA-256；只有文件内容完全一致时才会命中，与文件名、用户、RVC 模型、人声变调、BGM 变调和变速无关。命中后会跳过“去伴奏”和“去混响”，直接复用之前的干人声与伴奏。缓存默认不会自动过期。

在 AstrBot WebUI 的插件详情页打开“分离缓存”页面，可查看缓存歌曲名、搜索歌曲，并单独或批量清理缓存；也可以通过“清理全部缓存”释放全部空间。清理操作会等待当前翻唱任务结束，不会删除正在使用的音轨。升级后，后端会自动清理旧版无歌名记录的缓存。

同一时刻只执行一个 GPU 任务；后续请求会排队，避免分离模型和 RVC 模型同时抢占显存。
